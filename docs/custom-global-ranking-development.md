产品使用说明见[自定义排行榜](custom-ranking.md)，公式语法与函数见[指标公式规则](custom-ranking-formula-reference.md)，CSV 异常恢复与存储约束见[CSV 关联恢复维护说明](ranking-and-csv-recovery-development.md)。本文统一描述当前实现，不保留已被替代的阶段方案。

- 状态：ID 区间新版方案已实现；首次 detailbulk 建库、abstractbulk 同步、staticdetailbatch 补齐、范围保存 / 扩大范围与断点续传已接通，真实大范围采集待用户主动验收。
- 项目基线：元神助手当前版本 `1.4.0`；本方案不预定发布版本号。
- 官方依据：[录像数据爬取指南](https://openms.top/docs/zh/guide/development/data-crawling)。2026-11-17 已重新读取指南，采用其全量 / 增量批量接口方案；实施前仍须对照站点 API Schema 核对字段。
- 自动测试使用受控样本；真实采集、性能和浏览器验收见 §14–15。

## 1. 已确认需求

1. 加载全站所有玩家的公开录像数据，不限于当前玩家。
2. 按玩家排行，每位玩家占一行，使用站点玩家 ID 区分身份。
3. 用户可以添加多个自定义指标，使用接口提供的指标自由运算。
4. 配置指定唯一的默认排序指标；指标顺序只决定列顺序，不再逐级破同分。表头可临时切换当前排序指标。
5. 每个指标独立选择升序或降序，方向仅在指标设置中修改。
6. 按用户保存的录像 ID 区间批量采集；起始 ID 默认 1，首次填写结束 ID，之后同步复用，无需每次重填。支持扩大范围、暂停和断点恢复。
7. 采用独立页面；采集时保持页面打开，关闭后下次手动续传，不要求关闭页面后继续后台采集。
8. 采用本文默认筛选、无效值、并列规则；不应用本机统计排除。首版使用全局筛选和公式内条件，不提供逐指标筛选面板。

“所有录像”只包含接口允许读取的公开录像，不能承诺访问私有或未公开数据。最终结果必须说明扫描范围、时间和完整性；数据未加载完整时不能称为完整全站排名。

## 2. 首版范围与默认规则

本节产品规则已确认。模块命名、内部存储结构与资源预算可在开发中按实测调整，不得改变统计与交互语义。

### 2.1 实现范围

- 独立排行榜页面，用户主动启动采集，不随 popup、普通玩家页或 iframe 打开而自动抓取。
- 本地建立区间数据集，首次直接通过 detailbulk 建库，后续通过 abstractbulk 同步元信息并用 staticdetailbatch 补齐；支持暂停 / 继续、断点恢复、有限重试和持久缓存。
- 保留原始响应与规范化字段，使用受限表达式完成逐局计算和玩家聚合。
- 指标增删、列顺序调整、独立排序方向、显示精度、默认排序指标、字段帮助、模板和公式校验。
- 全局筛选、玩家结果分页（20 / 50 / 100 / 200）、当前榜单内玩家候选搜索与跨页定位、指标有效样本数与错误原因、玩家主页和已有分析页跳转。
- 多套命名配置，本地保存及配置导入 / 导出；导入先成为草稿，不自动联网或执行。
- 修改公式只计算本地已发布数据，不重新采集录像。

### 2.2 不纳入首版

- 云端采集服务、跨设备同步、排行榜公开分享、排名历史和定时无人值守更新。
- 下载或重新解析全站录像文件；图片分享和整份全站数据导出。
- 执行用户 JavaScript、任意网络函数、SQL 或嵌套聚合。
- 精确中位数、百分位、前 N 局均值等需要额外资源管理的聚合；后续单独扩展。
- 把全站数据直接塞入单玩家缓存，或逐个加载全站玩家页面来采集。

### 2.3 默认规则

| 项目 | 默认值 |
| --- | --- |
| 样本 | 公开、已审核 `state=c`、标准模式 `mode=00`、标准三级难度 |
| 3BV 下限 | 初始不限，用户显式设置；不继承大表下限 |
| 玩家集合 | 当前筛选后至少有一局的玩家，不枚举零录像账号 |
| 最少局数 | 1，可提高；每个指标另显示有效样本数 |
| 比较精度 | 未舍入值；通过公式 `round()` 主动指定并列精度 |
| 无效值 | 始终排在有效值之后；所有指标均无值的玩家不进入排名 |
| 并列名次 | 指标向量相同采用 `1、1、3`，玩家 ID 仅稳定展示顺序 |
| 本机统计排除 | 首版不应用，不提供开关，见 §9 |

## 3. 页面与操作

新增独立 `ranking.html`，在设置页、玩家页、popup 和 openms.top 排行榜页提供入口。popup 在「本地 CSV 分析」下方增加独立一行；站内排行榜页通过内容脚本和后台固定消息打开扩展页。页面沿用公共主题和“关于”卡片。

页面依次为排行榜、数据集、可折叠诊断和关于卡片。计算／计算当前部分数据／取消计算位于排行榜卡片；采集、范围与缓存操作位于数据集卡片，不保留重复入口。当前配置与筛选摘要始终可见；旧结果单独标明实际范围与结果口径。

配置选择、筛选、指标、字段帮助与公式错误收进默认关闭的侧栏。宽屏为非模态侧栏，≤900px 为覆盖式模态侧栏；支持 `aria-expanded`、Esc、焦点恢复、窄屏焦点约束与背景滚动锁。关闭及响应式模式切换清理锁定状态；隐藏控件、折叠 details 内部控件不可聚焦，summary 保持可操作。字段插入保留输入焦点与光标，进度变化不重建编辑控件。

站内入口仅在 HTTPS openms.top 顶层的 `#/ranking`、`#/ranking/` 及子路径出现，忽略查询参数；不匹配 `#/ranking-other` 或 iframe。按钮作为独立一行放在六个外层排行榜页签组上方，以导航区标签核验挂载点，内容表格不影响识别；没有可靠位置则等待，不按任意标题或 main 猜测。重绘后移动或恢复同一个节点，离开路由移除。后台校验扩展 ID、顶层 frame 和来源，只打开固定的 `ranking.html`。

popup 入口在 CSV 行之后、搜索结果之前；成功打开新标签页后关闭 popup，失败保留并提示，不携带搜索词、不触发采集。

1. 打开页面只恢复配置和最近成功数据集摘要，不自动联网。
2. 无数据时起始 ID 默认 1，用户填写结束 ID，显示扫描区间、预计批次数和最低等待时间，点击“开始加载”。
3. 采集期间可暂停 / 继续；已有成功数据和结果不被中间数据覆盖。
4. 设置全局筛选，编辑指标名称、公式、方向、精度及顺序。
5. 校验通过后点击“计算排行榜”；计算只读本地成功快照。
6. 分页查看名次、玩家、符合筛选的局数、各指标值和有效样本数。
7. 修改公式、指标集合或筛选后重新计算；显示与排序变化复用已有值。更新原始数据通过独立的“同步录像”操作完成。
8. “同步录像”直接复用已保存范围；“扩大范围”显示原结束 ID，输入更大结束 ID 后确认并同步。范围外的新录像不会自动纳入。
9. 有未完成任务时，“继续采集”恢复任务原范围与断点；修改范围必须暂停旧任务并另建新任务，不能改变运行中或续传任务的边界。

每项指标使用稳定内部 ID，名称重名不改变身份。字段面板按成绩、点击、局面、时间和来源分组，列出键名、含义、单位、类型和可空性，支持插入公式。

最多 10 项指标，每项公式最长 2000 字符、AST 最多 256 节点、嵌套深度最多 32。至少有一项合法指标才能计算。

## 4. 数据接口与限流

以下录像接口路径无结尾斜杠。`count` 是连续 ID 跨度，不是预期返回数量。

| 接口 | 参数与上限 | 用途 | 官方当前限流 |
| --- | --- | --- | --- |
| `GET /api/video/infobulk` | `first、count`，最多 2000 | 摘要和主要成绩 | 每 IP 每秒 1 次 |
| `GET /api/video/detailbulk` | `first、count`，最多 500 | 首次详细建库 | 每 IP 每秒 1 次 |
| `GET /api/video/abstractbulk` | `first、count`，最多 10000 | 玩家、审核和公开状态同步 | 每 IP 每 2 秒 1 次 |
| `GET /api/video/staticdetailbatch` | `ids`，最多 100 个 | 补齐缺少的解析字段 | 每 IP 每秒 5 次 |
| `GET /api/userprofile/infobulk` | `ids`，复用现有用户模块分批规则 | 补充玩家名称 | 复用现有模块限流 |

2026-11-17 已以 `first=379&count=1` 验证 infobulk、detailbulk、abstractbulk 均返回 200，`player` 为数值 ID。小批验证不代表已验证全部数据区间或当前全站规模。

请求要求：

- 匿名 GET，`credentials: omit`；遵守公开 CORS 白名单，不携带跨域登录凭据。
- 全任务共享串行调度器，每次响应完成后 detailbulk / infobulk 至少等待 1 秒，abstractbulk 至少 2 秒，staticdetailbatch 至少 0.25 秒；玩家资料接口按其限流等待。不同时并发调用多个接口叠加负载，429 时遵守退避，不通过并发绕过限制。
- 下一批按 `first += 本次请求跨度` 推进，最后一批缩小 count；不能按返回数量或返回最大 ID 推进。
- 空数组仅说明该区间没有公开记录，不能当作扫描结束标志。
- 429 优先遵守合法 `Retry-After`；网络、超时和 5xx 有限退避重试。失败区间不能当作成功空区间。
- HTML 错误页、非数组响应、越界 ID 和异常条目分别记录，不静默丢弃后声称完整成功。
- 浏览器自行协商压缩，不在前端手动设置 `Accept-Encoding`。
- 任务冻结源站命名空间；修改 API 根地址后，数据、缓存、锁和断点与原源站隔离。

## 5. 扫描边界与完整性

### 5.1 范围输入、保存与复用

- 界面使用包含两端的 `[startId, endId]`；内部统一为 `[startId, endExclusive)`，`endExclusive = endId + 1`。
- 起始 ID 默认 1；两端必须是正安全整数，起点不大于终点，endExclusive 也必须为安全整数。非法值不创建任务或发请求。
- 范围按源站保存，不随排行榜公式配置变化；重开页面恢复，不自动联网。范围不是某个玩家最大 ID，也不是全站权威上界。
- 首次点击加载或确认扩大范围时保存有效范围；编辑未确认时不影响已保存范围、已有任务或当前结果。
- 日常点击“同步录像”直接复用保存范围，无需重填；页面常显“当前扫描范围：1–N”，并说明范围外新录像尚未纳入。
- “扩大范围”保持起始 ID，要求新结束 ID 大于原值。确认后另建 generation，在整个扩大后的范围同步历史元信息，并补齐新增 ID 的详情。
- 首版不提供缩小范围或单独变更起始 ID的快捷操作；需要重新指定两端时通过“重新建库”明确确认，以新任务重新采集，不原地裁剪成功快照。
- 范围设置、任务冻结范围和成功数据集实际范围分别保存。扩大范围失败时保留新范围供重试，但旧榜单仍显示旧成功快照的实际范围。

### 5.2 范围与完整性声明

批量接口不提供最大 ID、全站总数或更新游标。不增加猜测上界的逻辑，不根据连续空批次结束扫描。只有扫描到用户确定的 endExclusive 才完成区间遍历。

页面完成文案为“ID X–Y 区间扫描完成”，不得写“已获取当前全站全部录像”。即使起点为 1，也不能证明结束 ID 之外没有录像。扫描分时进行，必须显示开始、结束和最后成功同步时间，不承诺网站原子时刻一致性。

| 状态 | 判断依据 |
| --- | --- |
| 区间覆盖 | 冻结范围内全部区间是否成功读取并持久化，空区间也记录成功 |
| 解析响应补齐 | 本轮公开 ID 是否仍有未取得的解析响应 |
| 字段可用性 | 公式需要的字段是否存在；合法 null 不等于请求失败 |
| 范围声明 | 显示实际起止 ID、范围外不覆盖及公开权限限制 |
| 新鲜度 | 开始 / 结束时间、成功同步时间、字段 Schema 版本 |

允许显式“计算当前部分数据”，但醒目标注未完成区间和缺失详情数，不覆盖旧成功结果或沿用其完整标记。空范围结果是合法空数据集；已完成区间没有公开录像不等于采集失败。

## 6. 建库、同步与任务状态

### 6.1 首次建库

1. 冻结源站、起止 ID、Schema 和任务 token，创建暂存 generation。
2. 从 startId 开始按最多 500 ID 的跨度请求 detailbulk，末批 `count = min(500, endExclusive - first)`；无需先请求 infobulk，也不读取全玩家目录和逐玩家录像列表。
3. 每批执行：请求 → 校验 → 原始及规范化记录写入 → 成功区间与进度同事务提交。只有提交成功才推进 first。
4. `first += 本次请求 count`，不能按返回条数或返回最大 ID 推进。空数组是合法成功区间，继续后续区间。
5. detailbulk 返回的记录直接构成本轮区间公开集合，不再与玩家录像索引求交。按录像 ID 去重；重复、越界、非法必要字段分别诊断，不静默忽略异常后宣称完整。
6. 从成功取得的录像中收集玩家 ID，通过 infobulk 分批补名称。名称失败可回退玩家 ID，不阻止录像完整性。
7. 全部区间完成且没有未解决的响应异常后，原子发布成功快照。

首次 detailbulk 没返回的 ID 可能不存在或未公开，不为每个空洞创建缺失详情任务。与后续“元信息已确认公开、但解析详情未取得”的情况分开处理。

### 6.2 后续同步与扩大范围

1. 固定基础成功快照与保存范围，创建新的暂存 generation。已有兼容快照时，“同步”和“扩大范围”均走本节流程；“重新建库”才强制重取全部详情。
2. 使用 abstractbulk 从 startId 按最多 10000 ID 扫描至 endExclusive，末批缩小 count。历史区间与新增区间都扫描，更新本轮公开 ID、player、upload_time 和 state。
3. 对本轮公开 ID 复用基础快照中版本兼容且语义稳定的解析字段；缺少响应或 Schema 过旧的加入补齐队列。改变玩家、审核状态不应迫使稳定解析字段全部重下，但必须更新规范化元信息。
4. 待补 ID 去重，每批最多 100 个，用 staticdetailbatch 获取。按 ID 合并，不依赖响应顺序。统一以最新元信息组装 player / state / upload_time 与解析字段，不能因补齐接口不返回元信息而使公式字段为空或沿用旧值。
5. 成功扫描区间中不再出现的旧 ID 不进入新公开集合；只能说明当前不可见，不能区分删除或转私有。失败区间不移除旧成功数据，也不发布拼接出的伪完整快照。
6. 补齐未返回的目标 ID 保持未完成；可有限重试，并通过 abstractbulk 重读其区间确认是否已经不可见。重读需同步处理该区间全部变化，不能只删除缺失目标。仍公开却缺解析响应的保持未完成。
7. 完成区间覆盖、必要补齐与响应校验后，原子发布新完整区间快照；失败保留上一份成功快照。部分数据需显式选择计算。
8. 根据本轮实际出现的玩家 ID 补名称，不逐玩家读取录像列表，不用 infoupdated 充当录像变更游标。

只扫描本地最大 ID 之后会漏掉历史审核、归属和公开状态变化，不作为完整区间同步。没有增加结束 ID 时，原范围以外的新增录像不会自动抓取。

abstractbulk 不含 ongoing_tournament，不把缺失当 false，也不提供无法证明的比赛筛选。以批量公开接口的访问权限为边界。不同详情接口的字段集合及标识字段名按 Schema 映射；可变元信息与稳定解析字段分开存储和更新。没有可靠来源的可变字段不能冒充最新值。

解析规则、单位或字段含义变化时提高 Schema 并重建受影响数据；不能只补新 ID。

### 6.3 暂停、恢复与发布

```text
首次：待开始 → detailbulk 区间扫描 → 玩家名称补全 → 可发布
同步：待开始 → abstractbulk 区间扫描 → staticdetailbatch 补齐 / 核对 → 玩家名称补全 → 可发布
                    ↕ 暂停 / 继续 / 退避重试
                    → 失败 / 取消
```

- 任务持久化采集策略版本、冻结范围、阶段、已成功区间、补齐队列及 token。录像与对应成功断点同事务保存。
- 续传恢复原任务、原范围和原 generation；无需重填。不把后来编辑或保存的范围混入旧任务。
- 扩大范围前先暂停旧任务；确认新范围另建任务，旧断点不冒充新区间覆盖。页面明确区分“继续原任务”和“按新范围同步”。
- 旧逐玩家实现的断点不兼容新策略，不直接续传；显示旧策略任务并允许删除或重新建库。已有成功数据仅在字段与 Schema 兼容时复用；旧快照无明确区间覆盖依据，不直接标记为新策略的完整快照。
- 暂停停止安排下一请求；取消、重建、删除或清缓存使任务 token 失效，晚到结果不得恢复任务或发布旧数据。
- 同源任意时刻仅一个写入任务，Web Locks 配合持久 token / 租约；发布事务再次校验任务有效性。
- 关闭页面后停在成功断点，重开只恢复状态，手动继续。不依赖 popup 或 service worker 永久存活，不挤占录像上传。
- 正在同步或同步失败时仍可查看上一成功榜单及其范围。新成功快照与暂存任务分开选择，进度不覆盖旧结果。

## 7. 字段模型

现有单玩家 `VideoDetail` 只保存部分字段，全站功能应使用独立字段注册表，不直接让现有大表类型承担所有未知字段。

字段至少登记：稳定键、中文名、类型、单位、可空性、来源接口、转换规则与 Schema 版本。保留原始 JSON；只有注册、校验过的字段进入表达式。接口新增字段先保留，核对后开放计算。

| 分类 | 当前字段示例 | 要求 |
| --- | --- | --- |
| 成绩 | `timems、bv` | 毫秒原值保留，派生 `time=timems/1000` |
| 点击 | `left、right、double、cl、left_ce、right_ce、double_ce、ce` | 区分接口原值与派生别名，核对含义后统一 |
| 局面 | `path、flag、op、isl、cell0…cell8` | null 保持未知；path 原始单位为 1/16 格 |
| 文件 | `file_size` | 字节单位，不混同其他文件长度 |
| 身份 / 状态 | `id、player、software、level、mode、state` | 条件判断按真实类型，不把代码字符串自动转成数值 |
| 时间 | `upload_time、end_time` | 保留原文，日期转换遵循统一时区规则 |
| 标识 | `video__identifier / identifier` 等 | 作为文本条件，不自动当作数字指标 |

这不是封闭字段清单，实施时应对照实际 Schema 列全。建议提供 `time、bvs、cl、ce、ioe、pathCells、nf` 等派生字段，缺少必要输入时返回 null，不套用展示代码中的 `?? 0`；`clicks` / `effectiveClicks` 仅作为兼容别名，与 `cl` / `ce` 共用类型和规范化结果。NF 等业务语义以已确认的项目定义为准，并说明哪些接口能可靠推导。

## 8. 公式语言与玩家聚合

### 8.1 两层表达式

逐局表达式计算单条录像，聚合函数再将一位玩家的录像压缩为标量。最终每个指标必须返回有限数值或 null。

```text
max(bv / time)
avg(bv / cl)
sum(bv) / sum(cl)
avg(if(level == "e", time, null))
max(bv / time) * 0.7 + avg(bv / time) * 0.3
```

裸用 `bv / time` 缺少玩家聚合方式，应提示选择 max、min、avg 或 sum，不能默认为某局或某种均值。`avg(bv/cl)` 与 `sum(bv)/sum(cl)` 含义不同，帮助文档必须说明。`clicks` / `effectiveClicks` 是 `cl` / `ce` 的兼容别名，旧公式继续可编译，但字段帮助和新模板只展示标准名。

### 8.2 首版语法

| 类别 | 支持内容 |
| --- | --- |
| 常量 | 有限数值、布尔、null；字符串仅用于条件 |
| 算术 | `+ - * / % ^`、一元正负和括号 |
| 比较 | `== != < <= > >=` |
| 逻辑 | `&& || !`，短路求值 |
| 条件 | `if(condition,a,b)`，仅计算命中分支；`isNull(expr)` |
| 数学函数 | `abs、sqrt、pow、log、exp、floor、ceil、round`，签名与参数范围固定 |
| 玩家聚合 | `count()、countValid(expr)、sum(expr)、avg(expr)、min(expr)、max(expr)` |

优先级固定为：括号 / 函数 → 幂 → 一元正负 → 乘除余 → 加减 → 比较 → 逻辑与 → 逻辑或。幂右结合，`2^3^2=512`、`-2^2=-4`；`^` 是乘方，不是 JavaScript 位异或。

- 原始录像字段只能出现在聚合参数内；聚合结果可继续数学运算。
- 禁止 `avg(max(bvs))` 等嵌套聚合；首版不支持指标相互引用，避免循环依赖。
- 禁止属性访问、下标、赋值、循环、函数定义、原型和全局对象访问、动态导入。
- 不使用 eval、new Function 或拼接脚本，遵守扩展 CSP。公式不能获得网络、DOM、存储或文件权限。
- 解析为受限 AST / 指令，编译一次后复用，不逐录像解析。语法、未知字段、类型和复杂度错误在计算前定位到指标与字符位置。
- 显示精度不影响排序；`round(expr,digits)` 才会改变计算值，digits 须为合理范围整数。

### 8.3 无效值

- null 参与算术时结果为 null，不能自动当成 0；null 比较不形成有效条件命中，需显式使用 isNull。
- 除零、NaN、Infinity、非法对数、负数开平方等使该行表达式无效，累计原因，不给出伪数值。
- 聚合跳过该表达式无效的录像；全部无效时 min、max、avg、sum 返回 null，countValid 返回 0。
- count 是当前全局筛选后的录像数；不等于每个聚合表达式的有效样本数。
- 聚合后的运算异常只影响该玩家该指标；某指标全员无值时提示检查公式。
- 预算超限或任务取消是计算未完成，保留旧结果，不能伪装成普通无效值。

## 9. 玩家、筛选与统计排除

按 player ID 分组，玩家名通过已有用户缓存或批量资料接口补齐；同名不合并、改名不改身份。名称缺失时使用 ID，不能导致录像聚合失败。

结果至少显示名次、玩家名 / ID、符合筛选的局数、各指标数值。展开或提示中显示指标有效样本数、单位与无效原因；提供站点主页和已有玩家分析入口。

全局筛选包括难度、模式、审核状态、软件、NF、日期和各级 3BV 下限。筛选显式展示，改变后仅本地重算。日期沿用结束时间优先、缺失回退上传时间的统一规则，本地自然日左闭右开；有日期限制时无有效日期的录像不参与。

非标准难度不能套用标准三级常数。批量接口缺少可靠比赛标记时，不提供伪比赛筛选，也不能宣称完全复现单玩家 PB 的比赛口径。

首版不应用本机“统计排除”，也不提供应用开关，避免不同电脑不知情地产生不同名次。网站及 CSV 的排除规则均保持原样，不读取、不修改；页面明确说明本榜未应用本机统计排除。不得隐式继承当前玩家页的筛选和数据源。

## 10. 单指标排序、分页与定位

配置通过 `defaultSortMetricId` 引用稳定指标 ID，指定唯一默认排序指标；`direction` 是该指标的排序方向，数组顺序只决定列顺序：

```json
{
  "metrics": [
    {"id":"speed","name":"最高 3BVS","formula":"max(bv / time)","direction":"desc","digits":3},
    {"id":"ioe","name":"平均 IOE","formula":"avg(bv / cl)","direction":"desc","digits":3},
    {"id":"games","name":"局数","formula":"count()","direction":"desc","digits":0}
  ],
  "defaultSortMetricId": "speed"
}
```

比较两位玩家只使用当前排序指标：

1. 有限数值按当前方向排列，0 和负数正常参与。
2. 空值与非有限值始终在有效值之后，不随方向反转。
3. 当前指标值相同，按玩家 ID 升序稳定展示；ID 不参与并列名次判断。
4. 有效数值相同使用 `1、1、3` 竞赛名次；当前指标为空的名次显示“—”。显示精度不改变比较值，用户可在公式中用 `round()` 指定并列精度。

不使用 epsilon 判断“近似相同”。全部指标都无值的玩家仍不参榜；全部指标被删除时停止计算并提示添加指标。

表头按钮只切换排序指标：点击其他指标采用该指标设置的排序方向，重复点击当前指标不反转；排序方向只在指标设置中修改，改当前指标方向立即重排，改其他指标方向只保存、等切换后生效。表头操作只改会话内排序，不写回配置，重新计算恢复配置默认。排序、分页与候选定位只读取已排序结果及玩家 ID → 实际数组位置，不重新扫描录像或联网。搜索只覆盖当前结果快照，按名称和十进制 ID 子串匹配，候选最多 8 项；选择后按数组索引计算目标页（`floor(index / pageSize)`），不能按并列名次推算。

### 10.1 分页、搜索与快照约束

- 每页 20 / 50 / 100 / 200，默认 20，本机偏好不进入公式配置导出；非法值回退 20。改变数量回到第一页、关闭候选并清除定位；空榜隐藏分页栏。
- 候选按不区分大小写的名称／十进制 ID 子串匹配；顺序为 ID 完全匹配、名称完全匹配、ID 前缀、名称前缀、其他子串，同组按榜单行序。最多 8 项，更多时提示缩小范围；不按拼音或编辑距离扩展匹配。
- 选择候选按玩家 ID 查当前数组位置，跳页、滚动、高亮并聚焦玩家链接；不筛选榜单。清空搜索不改页码；上下键／Enter／Esc 操作候选。
- 候选绑定结果、排序、每页数量和名称修订；过期时拒绝定位。排序、手动翻页、每页数量或结果变化清理旧定位；重复点击当前排序列不改变这些状态。
- 修改当前指标方向立即重排并清理分页／候选／高亮，修改非当前指标方向不抢占排序。重绘后恢复对应表头焦点，只有当前列设置 `aria-sort`。
- 指标值向量绑定稳定 metricId；新增指标 ID 不复用历史 ID，未计算的新列显示“—”且禁用排序。删除当前排序列后选已计算的默认指标，否则选可用列并提示；无可用列时清除排序与名次。
- 导出配置格式 v2；v1 保留原指标与列序，以第一项为默认排序指标，不再使用后续项破同分。未知更高版本拒绝导入。

## 11. 数据库与原子发布

当前实现已将共享数据库升级至 v7（排行榜 6 个 store 在 v6 引入，v7 为 CSV 关联元数据 / 句柄拆分新增 `csvSourceMeta`、`csvHandles`），包含以下 6 个排行榜 store。新版沿用统一 getDb 和阻塞处理，保留现有数据；任务 / 元信息增加范围及策略版本。若改变索引或 store 结构，再按开发时实际基线递增数据库版本，不重复创建已有 store。

| Store | 键 / 索引 | 内容 |
| --- | --- | --- |
| globalRankDatasets | datasetId；源站索引 | 实际起止 ID、策略版本、Schema、generation、完成状态与计数 |
| globalRankVideos | `[datasetId,videoId]`；`[datasetId,playerId]` 索引 | 快照独立的原始与规范化录像 |
| globalRankTasks | taskId | 冻结起止 ID、策略版本、token / 租约、阶段、错误及队列摘要 |
| globalRankTaskChunks | `[taskId,kind,chunkId]` | 成功 / 失败区间、详情补齐、玩家名称任务分块 |
| globalRankConfigs | configId | 带版本的指标、顺序、筛选和显示配置 |
| globalRankMeta | 源站 | 保存的起止 ID、当前成功数据集指针与修订 |

任务队列与区间记录需要分块，不能把数百万 ID 放进单个大对象。数据与区间进度同事务写入，进度通知不等于持久成功。

采用“成功快照 + 暂存 generation”：

- 同步时分批从基础快照复制 / 合并可复用字段，旧成功记录保持不可变。
- 全部必要步骤完成后，在元信息事务中校验源站、token、Schema 和完成状态，原子切换成功指针。
- 失败或取消不切换指针，旧榜单继续可用。部分结果必须使用独立标记，不能冒充完整结果。
- 通过读取租约或引用保护计算中的快照；新快照被接纳后再清理旧 generation，不能边计算边删数据。
- 按同时容纳旧成功与新暂存两份数据评估空间；空间不足时拒绝继续，不先删唯一成功快照。

提供“删除未完成任务”“清空全站录像缓存”“删除排行榜配置”独立操作，不影响单玩家缓存、用户资料、上传台账、CSV 句柄与排除规则；设置页“清空全部数据”也需同步明确新 store 的清理范围。

## 12. 计算、缓存与性能

用独立 Worker 分批读取 IDB，按玩家维护流式聚合器，不先组装每位玩家的全部录像数组。sum、count、min、max、avg 均可流式完成；多个指标在同一次数据扫描中计算并复用公共子表达式。

- 录像扫描约为 `O(N × 公式成本)`，单指标排序约为 `O(P log P)`。
- 聚合签名包含源站、数据集内容版本、字段 Schema、公式语言版本、筛选、指标 ID 集合与公式、有效局数阈值和排除策略；不含列顺序、默认指标、方向、精度和名称。
- 聚合值与排序视图分离：只改显示、方向、列顺序或默认排序时用已有值向量本地重排 / 重绘，不重新聚合；真正改公式、指标集合或筛选才使结果失效。
- Worker 返回携带请求版本，旧配置、旧数据集或已取消请求不能覆盖当前结果。
- 公式输入时只做校验，不逐字符重扫全站数据；计算进度按批次报告，可取消。
- 错误样本和日志设上限，不为每条异常录像永久记录一条日志。
- 通过 storage.estimate 评估配额；持久存储申请可能被拒绝，不能以其必然成功为前提。

对跨度 R，首次 detailbulk 请求数约为 `ceil(R / 500)`；同步 abstractbulk 请求数约为 `ceil(R / 10000)`，再加 `ceil(待补详情数 / 100)` 与玩家资料请求。界面分别显示区间覆盖进度和详情补齐进度，不把请求成功等同于写库成功。

100 万 ID 范围首次详情约 2000 次，仅 1.25 秒间隔约 42 分钟；同步元信息约 100 次，仅 2 秒间隔约 200 秒，另加网络、写库、补齐和重试时间。数字为理论量级，不承诺完成时间；压缩大小不等于内存和 IDB 占用。

## 14. 测试与验收

### 14.1 采集和存储

- 起止 ID 校验、默认起点 1、范围保存与重开恢复、不同源站隔离；日常同步不要求重填。
- 非 1 起点、短于单批的范围、末批缩小、空洞 / 空区间、乱序、重复和越界 ID；断点按请求跨度推进。
- 全历史元信息变化、归属转移、新公开 / 不再公开、详情元信息合并、补齐遗漏与合法 null。
- 扩大范围覆盖历史及新增区间；新范围失败保留旧范围榜单；旧任务续传不被范围编辑改变。
- 旧策略任务拒绝直接续传，旧成功数据仅作兼容字段复用，不能伪造区间覆盖。
- 超时、429、5xx、HTML、异常条目和写库失败不标记成功，不误删数据。
- 暂停、取消、重开、配额不足、多页面锁和迟到响应保持已提交断点。
- 历史归属、审核、可见性更新；补齐缺失响应与合法 null 分开处理。
- Schema 变化重建；generation 发布、失败回滚和旧快照清理保护读取任务。
- 数据库升级保留旧 store，清空全站缓存不损坏其他功能。

### 14.2 公式与聚合

- 用已知样本核对均值、比值均值与总和之比，不仅与实现自身互相比。
- 优先级、幂右结合、一元负号、短路分支、字段类型和函数参数。
- null、除零、NaN、Infinity、数学定义域、全部无效样本、count 与 countValid。
- 裸字段、嵌套聚合、全局 / 原型访问、动态调用及超长 / 超深表达式拒绝执行。
- 取消与超预算保留旧结果，非有限中间值不进入排序。

### 14.3 排序与交互

- 单指标排序下其他列不破同分；负数、零、null、非有限值与全员无值，空值不随方向反转。
- 比较器反对称性和传递性；ID 稳定展示、并列名次、精度不暗改计算值。
- 同名、改名、缺失玩家名和录像归属变化不合并错误玩家；候选按 ID 区分并按数组索引跨页定位。
- 默认 20 与 20 / 50 / 100 / 200 切换、偏好保存与非法回退；空榜隐藏分页。
- 只改显示、方向、列顺序、默认排序、分页和搜索不重扫录像；旧 Worker 结果不能覆盖新配置。
- 导入不自动联网；部分数据、普通空榜和计算失败文案明确区分。

### 14.4 性能与真实环境

## 15. 维护与待验收

- 区间提交、补齐、任务阶段和发布事务内校验任务与 token；清缓存后晚到响应不能恢复旧任务。
