# 全站自定义玩家排行榜

公式的字段、语法、函数、空值与样本数规则见[指标公式规则](custom-ranking-formula-reference.md)。

独立入口：设置页右上角「自定义排行榜 ↗」、玩家数据页头部、popup 的「自定义排行榜」行，或 openms.top 排行榜页的「自定义排行榜 ↗」。页面为 `ranking.html`，与单玩家分析页共用主题和「关于」卡片，不使用单玩家缓存，也不成为赛博大表的第九个页签。

## 页面结构

页头之后依次是排行榜卡片、数据集卡片、可折叠诊断和「关于」卡片。排行榜卡片置顶，计算操作、结果摘要、玩家定位搜索、表格和分页都在这里；「筛选与指标设置」按钮展开侧栏，配置选择、全局筛选、指标编辑、字段帮助和校验错误收在侧栏中，默认收起。

结果表上方可以搜索当前榜单内的玩家：输入名称或十进制 ID 显示最多 8 位候选，选中后跳到玩家所在页并高亮该行，不会筛掉其他玩家或重新计算。分页栏显示总人数、当前页和总页数，每页可选 20 / 50 / 100 / 200（默认 20），该选择作为本机偏好保存，不写入配置导出文件。

- 宽屏侧栏作为非模态布局展开，压缩结果区宽度；窄屏使用覆盖式模态侧栏，背景滚动锁定，Esc 或关闭按钮退出并恢复入口焦点。
- 侧栏关闭重开不重置编辑中的配置；收起侧栏不保存、不取消采集或计算，也不重置分页。
- 排行榜卡片始终显示当前配置名称和筛选摘要；已有结果同时显示实际范围、完整 / 部分状态。配置改变但未重算时保留旧结果并明确标记旧口径，不能用新筛选摘要冒充。
- 无数据时排行榜卡片仍置顶，引导到下方数据集卡片加载；打开页面不自动采集。

## 扫描范围

首版按用户保存的录像 ID 区间采集，不依赖玩家目录或最大 ID：

- 用户输入包含两端的 `[startId, endId]`；起始 ID 默认 1。两者必须是正安全整数，起始不大于结束，且 `endId + 1` 仍是安全整数。
- 首次点「开始加载」时保存范围；之后「同步录像」直接复用保存范围，不需要重填。
- 「扩大范围」保持起始 ID，要求新结束 ID 更大；确认后另建 generation，扫描历史与新增区间并补齐新增 ID 的详情。失败时保留新范围供重试，旧榜单仍显示上一份成功快照的实际范围。
- 「重新建库」才按表单范围重新抓取全部详情。未确认的表单编辑不会改变已保存范围、运行中任务或成功快照。
- 有未完成任务时「继续采集」恢复任务冻结的原范围和断点；修改范围必须另建任务，不会悄悄改变旧任务边界。
- 范围外的新录像不会自动纳入。只有扫描到用户确认的结束 ID 才算区间遍历完成，不能声称结束 ID 之外没有录像。

## 采集路线

首次建库：

1. 冻结源站、起止 ID、Schema 和任务 token，创建暂存 generation。
2. 从 startId 开始按最多 500 ID 的跨度请求 `detailbulk`，末批缩小 count。
3. 每批请求、校验、写入原始与规范化记录、推进成功区间和进度在同一事务中提交；只有提交成功才推进游标。
4. 空数组是合法成功区间；按 `first += 本次请求 count` 推进，不按返回条数或最大 ID。
5. detailbulk 返回的记录直接构成区间公开集合；越界、重复、缺少必要字段分别计入异常，不静默忽略后宣称完整。
6. 从取得的录像中收集玩家 ID，用 `infobulk` 分批补名称；名称失败回退玩家 ID，不影响录像完整性。
7. 全部区间完成且没有未解决异常后，原子发布成功快照。

后续同步与扩大范围：

1. 固定基础成功快照，创建暂存 generation。
2. 从 startId 开始按最多 10000 ID 请求 `abstractbulk` 扫描至 endExclusive，更新公开 ID、player、upload_time 和 state。
3. 对基础快照中版本兼容的稳定解析字段做复用，但用 abstractbulk 的最新元信息覆盖 player / state / upload_time；缺少详情的 ID 去重后用 `staticdetailbatch` 每批最多 100 个补齐。
4. 补齐响应统一以最新元信息组装记录；旧 ID 不在本轮公开集合中则不进入新快照。
5. 区间失败不发布拼接结果；旧成功快照保持可读。仍有缺失详情时保存为部分数据，可显式计算，但不能称为完整区间排名。
6. 玩家名称按本轮实际出现的玩家 ID 补全，不逐玩家读取录像列表。

采集需要保持页面打开；关闭后停在最后一个成功断点，下次手动继续。暂停停止安排下一请求。

## 全局筛选

先按以下条件筛选录像，再执行公式：

- 难度：初级 / 中级 / 高级；
- 审核状态：已审核、未审核、冻结、标识不符、外部审核；
- 模式：默认 `00`，可填写多个；
- 软件：全部或具体代码；
- NF：不限 / 只看 NF / 排除 NF；
- 日期：本地自然日，结束日期包含当天，左闭右开；结束时间优先，缺失回退上传时间，无有效日期的录像不参与日期筛选；
- 各级 3BV 下限：初始不限，不继承大表下限；
- 最少局数：默认 1。

筛选项改变只重算本地数据。全局筛选之上再用公式内的字段条件；首版不提供逐指标筛选面板。

## 公式

逐局表达式在玩家聚合函数内部计算，最终每个指标返回有限数值或 null。

```text
max(bv / time)
avg(bv / cl)
sum(bv) / sum(cl)
avg(if(level == "e", time, null))
max(bv / time) * 0.7 + avg(bv / time) * 0.3
```

支持数值、布尔、null、条件字符串；`+ - * / % ^`、比较、短路逻辑、`if`、`isNull`、数学函数和 `count` / `countValid` / `sum` / `avg` / `min` / `max`。原始字段只能出现在聚合参数内，禁止嵌套聚合、属性访问、赋值、循环、函数定义、全局 / 网络 / DOM / 存储访问和 eval / new Function。

`null` 参与算术仍为 null；null 比较不形成条件命中，用 `isNull` 判断。除零、非法对数、负数开平方、NaN / Infinity 都视为该行无效，不产生伪数值。`count()` 是当前筛选后的局数；`countValid(expr)` 只计非 null 的局数。结果表逐项显示有效样本数。

`round(expr,digits)` 会改变计算值；显示精度只影响展示，不参与排序。

`cl` 优先使用接口提供的有限数值；缺失或无效时由 `left + right + double` 得到。`ce` 优先使用接口值；缺失时由 `left_ce + right_ce + double_ce` 得到。派生所需任一字段缺失时返回 null，不补 0。字段帮助和模板只推荐 `cl` / `ce`；`clicks` / `effectiveClicks` 是兼容别名，任何单条录像都满足 `clicks == cl`、`effectiveClicks == ce`。旧快照在 Worker 和主线程计算前都经过同一规范化入口，不只修下一次采集的数据。

数值运算、`sum` / `avg` / `min` / `max` 和数学函数参数在编译期要求数值或可空数值；字符串字段只能用于字符串比较、`countValid`、`isNull` 或条件判断，`avg(software)` 这类确定类型错误会在计算前拒绝。指标最终结果必须是数值或 null。

## 排序与并列

排序只看一个指标：配置指定唯一的默认排序指标，指标顺序只决定列顺序。每个指标的升序 / 降序是它的排序方向，不再作为多级比较规则；方向只能在该指标的设置里修改。

1. 有限数值按当前方向排列，0 和负数正常参与；
2. 空值与非有限值始终排在有效值之后，不随方向反转；
3. 当前指标值相同按玩家 ID 升序稳定展示，ID 不参与并列名次；
4. 有效数值相同使用 `1、1、3` 并列名次，当前指标为空时名次显示“—”。显示精度不改变比较值，需要在公式里指定并列精度时用 `round()`。

点击指标表头只切换排序指标，采用该指标设置的方向：重复点击当前指标不会反转方向，也不会改变名次、页码、候选、定位高亮或焦点。表头排序只作用于当前会话，重新计算恢复配置默认；表头切换不修改配置的默认排序指标。

修改排序方向在指标设置里完成：改当前排序指标的方向会立即用已算出的指标值重排、回到第一页并关闭候选与定位高亮；改非当前指标的方向只保存设置，等切换到该指标时生效，即使改的是默认指标也不会抢走当前排序列。表头提示分别为“按此指标排序”和“当前排序指标，方向在指标设置中修改”。

删除当前排序列后会立即按仍可使用的默认指标重排；默认指标尚未计算时改按可用列并明确提示，不会继续按已删除的隐藏指标排名。所有指标都无值的玩家不进入榜单。旧版多指标优先级配置导入后只保留原第一项作为默认排序指标。

## 配置

- 最多 10 项指标，每项有稳定内部 ID、名称、公式、排序方向和 0–6 位显示精度；另有唯一的默认排序指标（引用指标 ID）；新增指标 ID 不会复用已删除指标的 ID；
- 多套命名配置保存在本机，侧栏中可选配置、新建、保存、删除；删除默认指标后回退到剩余第一项，并同步重排当前结果；
- 导入 JSON 只解析并校验为草稿，不自动保存、不联网、不执行公式；点「保存配置」才写入；旧版配置会迁移为单指标排序并给出提示；
- 导出包含格式版本、配置版本、语言版本和字段 Schema 版本；未知更高版本、字段或函数会拒绝；页面偏好不写入配置文件；
- 字段帮助按成绩、点击、局面、时间、身份、来源分组，点击字段插入当前公式。

## 计算与缓存

- 计算使用独立 Worker 扫描 IndexedDB，按玩家流式聚合；逐局筛选在聚合之前。
- 同步期间仍可计算上一份完整快照；有部分数据时可显式点「计算当前部分数据」。结果会标明实际范围和完整性。
- 名称、精度、方向、默认排序指标及列顺序变化都复用已有聚合值；名称／精度直接重绘，方向仅在当前排序列生效。公式、指标集合或筛选改变后保留标为旧口径的结果并提示重新计算，旧的晚到 Worker 结果不会覆盖新配置。
- 计算只读本地数据集，不重新联网。

## 明确不提供的功能

- 云端采集、跨设备同步、公开分享、排名历史、定时无人值守更新；
- 把结束 ID 当作全站权威上界，或根据连续空批次推断扫描结束；
- 用户 JavaScript、SQL、任意网络函数；
- 中位数、百分位、前 N 局均值等需要额外资源管理的聚合；
- 应用本机「统计排除」（网站和 CSV 的排除规则仍按原样保留，但本榜不读取、不修改）。

## 存储与清理

全站排行榜使用共享数据库 v7 的 `globalRankDatasets`、`globalRankVideos`、`globalRankTasks`、`globalRankTaskChunks`、`globalRankConfigs`、`globalRankMeta`。范围按源站保存在 `globalRankMeta`，任务保存冻结范围和策略版本，数据集保存实际成功范围。删除未完成任务、清空全站录像缓存、删除配置是独立操作；“清空全站缓存”不删除已保存配置和范围。设置页“清空全部数据”会连同全站排行榜缓存和配置一起清理。

## 已知限制

- 公开接口可能限流、超时或改变字段；失败区间不会当作成功空区间。
- 结束 ID 是用户确认的扫描边界，不是网站权威上界；范围外可能仍有录像。
- 部分数据的计算是明确允许的，但不能称为完整全站排名。
- 旧逐玩家策略的任务不会被直接续传，也不会被当作新版完整区间快照。
- 真实大范围采集需要用户主动触发；自动测试只使用受控 ID 区间和合成数据。
