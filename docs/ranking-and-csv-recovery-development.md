# CSV 关联恢复与存储维护

- 更新日期：2026-11-19。
- 状态：实现及自动检查完成；用户原 Chrome 配置中的异常恢复仍待真实验收。
- 排行榜排序、布局和站内入口规则已并入[排行榜技术说明](custom-global-ranking-development.md)；产品操作见[玩家数据说明](player-stats.md#本地-csv)。

## 1. 恢复目标

CSV 刷新、授权、身份比较或句柄保存失败时，提供可取消、可重试的管理与修复流程，保留来源顺序、排除规则和上次成功统计。不能要求用户卸载扩展、清空全部数据或更换 Chrome 用户。

已观察到的原配置异常包括权限查询无返回、打开文件超时、`isSameEntry()` 中止，以及移除来源时 `Failed to write blobs (Error)`。另一 Chrome 用户配置可以读取，但其权限、数据库和文件句柄独立，不能据此断定旧窗口、数据库或排行榜代码是根因。

本地 CSV 每一行仍是独立的一局；不进行内容去重。不按同名、相似内容、旧行号或临时负 ID 判断文件身份和排除目标。

## 2. 数据与兼容

| 数据 | 存储与职责 |
| --- | --- |
| 关联元数据 | `csvSourceMeta` 的 current 记录：来源 ID、顺序、名称、来源 revision、上次摘要、显式排除作用域 ID；不嵌入文件句柄 |
| 当前文件句柄 | `csvHandles` 按 sourceId 独立保存；只有新增或替换该来源时写入 |
| 历史关联 | `csvSources` 的旧记录保持只读，用于兼容迁移及失败回退 |
| 排除规则 | `statExclusions` 保存作用域 owner、规则目标和锚点；不随移除当前关联自动删除 |

共享数据库 v7 新增元数据和句柄 store，保留其他数据。缺少句柄的来源仍保留元数据并显示待修复，不能直接丢掉来源或将其视为空文件。

迁移对每个句柄单独处理，事务内不覆盖已有新句柄；保存元数据前在同一事务内复查迁移标记。另一页面已迁移或修改清单时返回当前版本，不覆盖来源／revision；清理迟到迁移生成的孤儿句柄。新记录成功前不删除旧记录，不能同时把旧、新记录计入统计。

来源移除仅更新元数据并删除该来源句柄；摘要刷新仅更新元数据，不重新序列化无关来源的句柄。

## 3. 来源、规则与 owner

- `sourceId` 是来源身份；重新关联保留 sourceId、位置和添加时间，提升来源 revision。
- 同一真实文件优先用 `isSameEntry()` 确认。身份比较失败不是“不同文件”，中止错误也不是用户主动取消。
- 显式保存的 `exclusionScopeId` 优先绑定。旧来源没有显式绑定时，可核对 `csv|sourceId|sourceRevision` 的历史身份；owner.sourceId 存在时也须一致。来源版本不同不能自动认领旧作用域。
- 一个当前作用域不能绑定两个来源。用户确认“沿用”后按新文件逐条匹配原规则；缺失和歧义目标保留未匹配，不猜测排除。
- “作为新来源”不继承原规则，但保留历史作用域。
- 沿用规则修复或重新关联时，作用域 owner 的文件名、句柄和来源 ID 与当前关联一起替换；保留规则 ID、目标及锚点，提升作用域 revision。
- 关联历史规则到当前文件时同样更新 owner。否则后续锚点提交会重新写入坏旧句柄。
- 普通规则提交不自动比较句柄。仅显式 `rebindOwner` 支持规则未变、只更新 owner 的提交；引用一致且其余 owner 字段不变时不重复提升 revision。

## 4. 操作流程

### 4.1 刷新与授权

打开页面只恢复关联与摘要，不自动读取或弹授权框。刷新显示检查关联、检查权限、读取具体文件、保存及完成状态；成功时明确局数变化或局数未变。

权限查询超时不等于被拒绝，可尝试实际 `getFile()`，由浏览器校验读取权限。确定缺少权限时保留行内“授权读取”；授权失败或超时不移除该入口，也不覆盖旧统计。不在后台自动申请新权限。

完整批次读取成功后一次提交摘要及快照；任一文件失败不拼接新旧成绩。正确表头的 0 行文件仍是合法来源。

### 4.2 单个重新关联与批量修复

“修复文件关联”按待修复来源逐行展示“原来源 → 新选择文件”、规则数量和沿用／新来源选择。各行由用户点击打开选择器，以保留浏览器要求的用户手势。

1. 冻结清单及来源版本，收集每个来源的新句柄。确认身份相同可默认沿用；不同或未知时由用户明确选择，有规则时不能静默继承。
2. 本批新句柄彼此检查重复，完整读取、解析各文件。
3. 只修复部分来源时，与其余当前句柄检查重复；旧句柄无法比较或缺失时要求一并修复，不把未知当作不重复。
4. 全部校验成功后，原子替换本批句柄、来源元数据及沿用作用域的 owner。
5. 提交后重读排除规则，再匹配新快照并完成必要的锚点提交，最后发布统计。事务期间只更新进度，不提前发布新统计。

涉及全部当前来源时不依赖旧句柄完成排重。单个重新关联沿用相同的版本、身份与事务约束。取消、读取失败和并发冲突均保留原关联；读取失败与存储失败给出具体文件或阶段。

“清空关联清单”只取消当前文件关联，保留历史排除规则、排行榜数据和配置，不能等同于设置页“清空全部数据”。

## 5. 事务与异步约束

- 写事务覆盖当前操作涉及的元数据、句柄及作用域，按需获取 store。
- 第一步只读取和校验全部作用域 revision、清单 revision、来源 revision、唯一绑定和批次有效性，不写任何记录。
- 第二步才写入清单、本批句柄和 owner；任一校验失败前必须没有写入。写入异常显式 abort，等待事务结束后再返回失败。
- 清单、来源、规则修订以及操作标记共同拒绝过期结果；取消、切源、销毁、移除及其他页面更新不能被晚到操作覆盖。
- 活跃统计与待发布快照分离；锚点提交失败保留旧统计及待重试依据，不使用过时锚点自动排除重复条目。
- 使用统一的 CSV 超时封装释放计时器。查询权限 5 秒、授权 30 秒、打开文件 15 秒、身份比较 8 秒、关联存储 15 秒。
- 超时与用户取消分别反馈；存储超时使事务有效性守卫失效，晚到结果不能发布。阶段提示不等待规则处理；保留取消入口。
- 多页面通知只携带作用域／清单修订，接收方重读数据库，不广播句柄或成绩。

## 6. 验证与待验收

关键自动回归保留以下组合：

- 旧句柄写入失败：移除、摘要更新和其他来源修复不重写它。
- 两份旧句柄同时异常：整批选择新文件、拒绝批内重复、保持顺序和规则继承，修复后追加及重开仍能刷新。
- 首次迁移与另一页面移除、清空、重新关联交错：来源不复活、revision 不倒退、新句柄不被覆盖。
- 坏句柄不可比较或缺失：仍能通过可核验历史身份找到规则。
- 清单冲突、后续作用域冲突、句柄同步写入失败：所有记录原样保留。
- 权限、打开文件、身份及存储等待中取消／超时／切源：提示明确，晚到结果不覆盖新状态。
- 修复期间读取或锚点失败：不发布半批统计，保留旧结果。

最终执行 `npm run verify` 和 `git diff --check`。真实验收必须使用用户原 Chrome 配置中的那两份异常 CSV，覆盖规则沿用、局数与摘要、追加刷新、重开恢复、失败及取消。新配置正常或模拟句柄通过不能替代该验收；未通过前不标记原故障已解决。

提交、推送、版本号和发布由用户另行指示。此文只维护最终行为、兼容与恢复约束，不记录逐轮修复日志或重复测试计数。
